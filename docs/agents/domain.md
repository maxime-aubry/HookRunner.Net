# Domain docs

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root for domain vocabulary.
- `docs/adr/` for architecture decision records.

## Before exploring

Read the glossary and ADRs relevant to the area being explored.
If they do not exist, proceed silently. The domain-modeling skill
creates them progressively as terms and decisions are resolved.

## Vocabulary

Use glossary terms consistently in issues, proposals, code, and tests.
If a concept is missing, reconsider the term or record the gap for
domain-modeling.

## Decisions

When a proposal conflicts with an existing ADR, identify the ADR
and explain why the decision should be reconsidered.
